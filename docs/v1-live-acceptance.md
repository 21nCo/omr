# OMR v1 live acceptance (OMR-15, final run in OMR-27)

**Decision: HOLD. Do not release or roll forward to production.** This record covers the OMR-15 live runs on 2026-10-09, 2026-10-10 and 2026-10-13 and the fixes from them that landed in OMR-24, OMR-25 and OMR-26. It does not authorize production deployment or v1-ready provider exposure, and OMR-1 remains In Progress. Keep the GitHub, Linear, Slack, Notion, vault, direct playground and assisted playground rollout switches disabled in staging and production. The rollback position is the current one: every v1 rollout switch off. The runs observed only part of that: on the 2026-10-09 and 2026-10-13 Previews, with the vault cache confirmation set, the vault switch off returned 503 `OPENROUTER_VAULT_DISABLED`. No run observed another switch's disabled response. On 2026-10-13 GitHub read back `unconfigured` because its switch was on and no client secret was bound, so that is not a switch observation; the 2026-10-10 run was local only. A per-switch readback is OMR-27 gate 4. Lifting the hold needs a passing exact-head OMR-27 receipt and a separate production authorization; Linear, Slack, Notion and Windows also need their own acceptance issues below.

## Reusable Preview and database procedure

2. TLS: create a short-lived disposable CA and a server certificate for the TCP proxy host. Create the proxy with `tcpProxyCreate` (`applicationPort: 5432`), pass the certificate and key as service variables, start PostgreSQL with `ssl=on` and those files, and redeploy.
